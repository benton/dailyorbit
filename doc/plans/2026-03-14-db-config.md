# Plan: DB-Backed Configuration System

## Context

All app configuration currently lives in `.env` files read via `@nkzw/define-env`. This is fragile (env vars are easy to misconfigure), not hot-reloadable, and not GUI-editable. The goal is to move all user-facing config into the DuckDB `config` table, encrypted where needed, with only two filesystem paths (DB file + key file) as CLI args. This enables a web-based config editor and hot-reload.

## Current Config Points

| Env Var | Disposition | Encrypted? |
|---------|------------|------------|
| `DATABASE_URL` | Replaced by CLI positional arg (already done) | N/A |
| `BETTER_AUTH_SECRET` | Store in DB `config` table | **Yes** |
| `BETTER_AUTH_URL` | Store in DB `config` table | No |
| `CLIENT_DOMAIN` | Store in DB `config` table | No |

**Stays as env var / CLI flag (not in DB):**
- `--port` flag on serve command (default `9000`) — CLI flag only, deployment-specific
- `NODE_ENV` — framework-level, used before any app code runs
- `VITE_SERVER_URL` — compile-time constant baked into the frontend bundle by Vite

### Framework env var discussion

Framework-specific env vars like `NODE_ENV` and `VITE_*` vars cannot move to the DB because they're consumed at build time or by the runtime before our app code executes. These stay as traditional env vars. The only way to "override" them is the standard way: set them in the shell or `.env` file before starting the process. This is fine — they're infrastructure concerns, not app configuration.

## Implementation Steps

### Step 1: Add encrypt/decrypt to encryption module

**Modify:** `packages/server/src/lib/encryption.ts`

Add two functions using AES-256-GCM (Node.js `node:crypto`):
- `encrypt(plaintext: string, key: Buffer): string` — generates random 12-byte IV, encrypts, returns base64 of `iv || authTag || ciphertext`
- `decrypt(ciphertext: string, key: Buffer): string` — decodes base64, slices IV + authTag, decrypts

**New test:** `packages/server/src/lib/encryption.test.ts`
- Round-trip, different plaintexts produce different ciphertexts (random IV), tampered data throws, wrong key throws

### Step 2: Define config schema

**New file:** `packages/server/src/lib/config-schema.ts`

Single source of truth for all config keys:

```typescript
type ConfigFieldDef = {
  readonly key: string;
  readonly defaultValue: string;
  readonly encrypted: boolean;
  readonly description: string;
};

export const CONFIG_SCHEMA = {
  betterAuthSecret: { key: 'betterAuthSecret', defaultValue: '', encrypted: true, description: 'Auth secret (auto-generated on first start)' },
  betterAuthUrl:    { key: 'betterAuthUrl',    defaultValue: 'http://localhost:9000', encrypted: false, description: 'Auth service base URL' },
  clientDomain:     { key: 'clientDomain',     defaultValue: 'http://localhost:5173', encrypted: false, description: 'Frontend domain for CORS' },
} as const;

export type ConfigKey = keyof typeof CONFIG_SCHEMA;
```

### Step 3: Config repository (data access)

**New file:** `packages/server/src/lib/config-repository.ts`

Repository pattern (rule D-1) with parameterized SQL queries:
- `getConfigValue(conn, key)` → `{ value, encrypted } | null`
- `setConfigValue(conn, key, value, encrypted)` → upsert
- `getAllConfig(conn)` → all rows
- `deleteConfigValue(conn, key)` → remove

**New test:** `packages/server/src/lib/config-repository.test.ts` (in-memory DuckDB per D-3)

### Step 4: Config service (business logic)

**New file:** `packages/server/src/lib/config-service.ts`

```typescript
export class ConfigService {
  private cache: Map<string, string>;
  constructor(db: DuckDBInstance, encryptionKey: Buffer);

  async load(): Promise<void>;       // Read all from DB, decrypt, populate cache
  get(key: ConfigKey): string;        // Sync read from cache (fast)
  async set(key: ConfigKey, value: string): Promise<void>;  // Persist + update cache
  async reload(): Promise<void>;      // Re-read all from DB (hot-reload)
}
```

- `load()` reads all rows, decrypts encrypted values, fills cache. Missing keys get defaults from `CONFIG_SCHEMA`.
- `get()` is synchronous — reads from in-memory cache, no DB hit.
- `set()` encrypts if schema says so, writes to DB, updates cache.
- `reload()` clears and re-populates cache from DB.

**New test:** `packages/server/src/lib/config-service.test.ts`

### Step 9: Update serve command

**Modify:** `packages/server/src/cli/serve.ts`

New startup sequence:
1. Parse DB path + key path (positional args), validate both-or-neither
2. On fresh init: create dirs, generate key, init DB schema, seed default config
3. `setDbPath()` + `getDb()`, `readKeyFile()`
4. Create `ConfigService(db, key)`, call `config.load()`
5. `setConfigService(config)`, `initializeAuth(config)`
6. Import app, start server on CLI `--port`
