# Newspaper Images → CloudFront Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Serve all newspaper images (library + edition) from the CloudFront CDN instead of the API server, and upload them to S3 as part of the generation pipeline.

**Architecture:** Images are uploaded to the existing frontend S3 bucket (`daily-orbit-prod-frontend`) under a `newspaper/images/` prefix. CloudFront already serves this bucket at `dailyorbit.org`. Frontend URL helpers switch from `api.dailyorbit.org/api/newspaper/images/...` to `dailyorbit.org/newspaper/images/...`. Generators auto-upload after writing to disk. The API image-serving routes remain as a dev-mode fallback.

**Tech Stack:** AWS SDK v3 S3 client, existing CDK stack (CloudFront + S3), Hono routes, Vite env vars, GitLab CI

---

## Context

### Current Deploy Flow

```
git tag v1.x.x && git push --tags
  → GitLab CI: test (pnpm test) + build (Docker image, arm64)
    → Manual gate: deploy job
      1. Push image to ECR
      2. Extract frontend from Docker image → aws s3 sync to daily-orbit-prod-frontend
      3. Invalidate CloudFront /index.html
      4. Trigger ASG instance refresh (new EC2 boots, pulls from ECR, restores DB from S3)
```

Key: The frontend is built inside the Docker image with `VITE_SERVER_URL` as a build arg, then extracted during deploy. Newspaper images are generated at runtime on EC2, not at build time.

### Current State
- Images generated by `./daily-orbit newspaper generate` and `./daily-orbit newspaper generate-library`
- Written to local filesystem: `data/newspaper/images/{date}/` and `data/newspaper/images/library/`
- Served by API server routes: `GET /api/newspaper/images/:date/:filename` and `GET /api/newspaper/images/library/:subpath`
- Frontend builds URLs via `editionImageUrl()` and `libraryImageUrl()` in `packages/web/src/newspaper/types.ts`
- No S3 upload exists for newspaper images
- No backup/restore for images (lost on instance replacement)

### Target State
- Images uploaded to S3 bucket `daily-orbit-prod-frontend` under `newspaper/images/` at generation time
- Served by CloudFront at `dailyorbit.org/newspaper/images/...` (same-origin, no CORS, global CDN)
- **Edition images** (hero, cartoon): auto-uploaded to S3 by generators at runtime on EC2 — fully automatic
- **Library images** (portraits, headers, house-ads, masthead): generated on production via CLI, auto-uploaded to S3 by generators (same mechanism as edition images)
- CLI command `newspaper sync-images` for bulk upload / migration / recovery
- API image-serving routes remain for local dev (when `VITE_NEWSPAPER_IMAGES_URL` is unset)

### Two Categories of Images

| Category | Examples | Generated | Upload to S3 |
|----------|----------|-----------|-------------|
| **Edition** | hero.webp, editorial-cartoon.webp | Automatically by nightly scheduler on EC2 | Automatic (generator auto-uploads) |
| **Library** | portraits/000.webp, headers/three-miles-up.webp, house-ads/000.webp | On production via `./daily-orbit newspaper generate-library` | Automatic (generator auto-uploads, same as edition) |

**Library images must be generated on production**, not on a dev machine. This keeps DB rows (metadata) and image files together — the DB is backed up with S3 snapshots, and the auto-upload (Task 3) pushes images to the CloudFront S3 bucket immediately. Generating locally would strand DB rows in a local DuckDB with no way to sync them to prod.

Since image generation is seeded and deterministic, generating on prod produces the same results as generating locally. When testing generation, use `--limit 1` or `--limit 3` to avoid burning through Bedrock quota — there's no need to generate the full set just to verify the pipeline works.

### How This Fits the Deploy Flow

The existing tagged-commit → CI → deploy pipeline gains two small additions:

1. **Build-time (CI change):** `VITE_NEWSPAPER_IMAGES_URL=/newspaper` added as a Docker build arg and CI variable. The frontend gets built with CloudFront image URLs instead of API server URLs.

2. **Runtime (no CI change):** Generators on EC2 auto-upload edition images to S3 when `newspaperImagesBucket` is configured in the DB. This happens during scheduled pipeline runs. No CI involvement needed.

3. **Library images (on prod, when needed):** SSH into prod and run `./daily-orbit newspaper generate-library`. The generators auto-upload to S3 (same as edition images) and insert DB rows in the same transaction. No separate sync step needed. The `make deploy-newspaper-images` target remains available as a fallback for bulk re-sync or recovery.

The `newspaperImagesBucket` config value is stored in DuckDB, backed up with DB snapshots, and restored on instance boot. Set it once; it persists across all future deploys.

```typescript
import { readFile } from 'node:fs/promises';
import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';
import { getLogger } from '../lib/logger.ts';

const CONTENT_TYPES: Record<string, string> = {
  '.webp': 'image/webp',
  '.png': 'image/png',
  '.jpg': 'image/jpeg',
  '.jpeg': 'image/jpeg',
};

/**
 * Extract the S3 key from a local image path.
 * Strips everything before "newspaper/images/".
 */
export function imageS3Key(localPath: string): string {
  const marker: string = 'newspaper/images/';
  const idx: number = localPath.indexOf(marker);
  if (idx === -1) {
    throw new Error(`Path does not contain '${marker}': ${localPath}`);
  }
  return localPath.slice(idx);
}

/**
 * Upload a single newspaper image to S3.
 * Returns the S3 key on success.
 */
export async function uploadNewspaperImage(
  localPath: string,
  bucket: string,
  region: string,
): Promise<string> {
  const log = getLogger();
  const key: string = imageS3Key(localPath);
  const ext: string = localPath.slice(localPath.lastIndexOf('.'));
  const contentType: string = CONTENT_TYPES[ext] ?? 'application/octet-stream';

  // Library images are immutable; edition images change at most once per day
  const isLibrary: boolean = key.includes('/library/');
  const cacheControl: string = isLibrary
    ? 'public, max-age=31536000, immutable'
    : 'public, max-age=86400';

  const body: Buffer = await readFile(localPath);
  const client: S3Client = new S3Client({ region });

  await client.send(
    new PutObjectCommand({
      Bucket: bucket,
      Key: key,
      Body: body,
      ContentType: contentType,
      CacheControl: cacheControl,
    }),
  );

  log.info({ key, bucket }, 'Uploaded newspaper image to S3');
  return key;
}
```

**Step 1: Create the shared helper**

This reads config once and provides a fire-and-forget upload function:

```typescript
import { getConfigService } from '../../lib/config.ts';
import { uploadNewspaperImage } from '../image-upload.ts';
import { getLogger } from '../../lib/logger.ts';

/**
 * Returns an upload function that sends images to S3 if configured,
 * or a no-op if newspaperImagesBucket is empty.
 */
export function createImageUploader(): (localPath: string) => Promise<void> {
  const config = getConfigService();
  const bucket: string = String(config.get('newspaperImagesBucket') ?? '');
  const region: string = String(config.get('bedrockRegion') ?? 'us-east-2');

  if (!bucket) {
    return async () => {};
  }

  const log = getLogger();
  log.info({ bucket }, 'Newspaper image S3 upload enabled');

  return async (localPath: string): Promise<void> => {
    try {
      await uploadNewspaperImage(localPath, bucket, region);
    } catch (err: unknown) {
      const msg: string = err instanceof Error ? err.message : String(err);
      log.warn({ error: msg, localPath }, 'Failed to upload newspaper image to S3');
    }
  };
}
```

**Step 1: Add the sync command**

```typescript
const syncImages = defineCommand({
  meta: {
    name: 'sync-images',
    description: 'Upload all local newspaper images to the configured S3 bucket',
  },
  args: {
    database: { type: 'positional', description: 'Path to DuckDB database file', default: DEFAULT_DATABASE, required: false },
    keyFile: { type: 'positional', description: 'Path to encryption key file', default: DEFAULT_KEY_FILE, required: false },
  },
  async run({ args }) {
    // Bootstrap DB + config (same pattern as other newspaper commands)
    // ...

    const config = getConfigService();
    const bucket: string = String(config.get('newspaperImagesBucket') ?? '');
    const region: string = String(config.get('bedrockRegion') ?? 'us-east-2');

    if (!bucket) {
      log.error('newspaperImagesBucket is not configured — set it via: ./daily-orbit config set newspaperImagesBucket <bucket-name>');
      process.exit(1);
    }

    const imagesRoot: string = resolve('data', 'newspaper', 'images');
    const { glob } = await import('node:fs/promises');
    let uploaded: number = 0;
    let failed: number = 0;

    for await (const filePath of glob(resolve(imagesRoot, '**/*.{webp,png,jpg,jpeg}'))) {
      try {
        await uploadNewspaperImage(filePath, bucket, region);
        uploaded++;
      } catch (err: unknown) {
        const msg: string = err instanceof Error ? err.message : String(err);
        log.warn({ error: msg, filePath }, 'Failed to upload');
        failed++;
      }
    }

    log.info({ uploaded, failed, bucket }, 'Image sync complete');
  },
});
```

function newspaperImagesBase(): string {
  const cdnBase: string = env('NEWSPAPER_IMAGES_URL');
  if (cdnBase) return cdnBase;
  return `${env('SERVER_URL')}/api/newspaper`;

/** Build URL for an edition image from its filesystem path */
export function editionImageUrl(editionDate: string, imagePath: string): string {
  const filename: string = imagePath.split('/').pop() ?? imagePath;

}

/** Build URL for a library image */
export function libraryImageUrl(subpath: string): string {
  return `${newspaperImagesBase()}/images/library/${subpath}`;
}

## Task 6: Add CloudFront cache behavior for newspaper images

The default CloudFront behavior has SPA error fallbacks (403→/index.html with TTL 0). Adding a dedicated behavior for `newspaper/images/*` provides:
- Proper 404s for missing images (not HTML)
- Long-lived caching (images are immutable or daily)
- Compression for WebP

**Files:**
- Modify: `deploy/lib/stack.ts`

**Step 1: Add the cache behavior**

In the CloudFront distribution config, add `additionalBehaviors`:

```typescript
additionalBehaviors: {
  'newspaper/images/*': {
    origin: origins.S3BucketOrigin.withOriginAccessControl(frontendBucket),
    viewerProtocolPolicy: cf.ViewerProtocolPolicy.REDIRECT_TO_HTTPS,
    cachePolicy: cf.CachePolicy.CACHING_OPTIMIZED,
    compress: true,
  },
},
```

This behavior does NOT inherit the custom error responses from the default behavior, so missing images return real 403/404 instead of /index.html.

Newspaper images (portraits, section headers, hero images, editorial cartoons) are

| Environment | Image URL pattern | Served by |
|---|---|---|
| Production | `dailyorbit.org/newspaper/images/...` | CloudFront → S3 |

- Set `VITE_NEWSPAPER_IMAGES_URL` to empty string in `.gitlab-ci.yml` and redeploy → frontend reverts to API server image URLs
- API image-serving routes are untouched and continue working
- No data is lost — images remain on local filesystem and in S3
